# PREP — صفحة الهبوط

صفحة هبوط عربية (RTL) بـ HTML/CSS/JS بلا إطار عمل ولا خطوة بناء، مربوطة بقناة الدفع من
الموقع في الباك إند (**CN-001**) في مستودع `Standardized-Tests-Preparation-Platform`.

الإعداد الوحيد الذي يتغيّر عند النشر: `assets/js/config.js`.
تفاصيل العقد وقائمة ما قبل الإطلاق: [docs/BACKEND_CONTRACT.md](docs/BACKEND_CONTRACT.md).

---

## 1. الحالة الحالية

**يعمل الآن:**

- الدورات والباقات وأسعارها ومددها تُقرأ من `GET /public/web-offers` — لا سعر مكتوب في HTML.
- صفحة الشراء: بريد حساب التطبيق مرتين + الموافقة على شروط العرض القادمة من الباك إند.
- إنشاء الطلب، والتحويل إلى صفحة الدفع، وقراءة حالة الطلب من الباك إند وحده.
- شاشات النتيجة: نجاح · فشل · قيد المعالجة · يحتاج مراجعة · استرداد.
- `account.html` صفحة إرشاد (لا سجل مشتريات على الموقع — بقرار الباك إند).

**لم يُختبر بعد:** الدفع الفعلي حتى شاشة النجاح. المزوّد الحالي `fake` يُصدر رابط دفع وهمي
(`https://fake-checkout.localhost/...`) لا يفتح في المتصفح.

## 2. الناقص من الباك إند

### 2.1 حاجز يمنع البيع اليوم

**لا يُنشأ حساب عند الشراء.** `_resolve_recipient` في `app/services/web_checkout.py` يرفض أي بريد
لا يقابله حساب طالب موجود، ويردّ `409 CHECKOUT_UNAVAILABLE`. والتعليق في الكود صريح:
«A checkout that could create a student would be a registration endpoint with no password».

النتيجة: **قبل نشر التطبيق لا يستطيع أي زائر إنشاء حساب، فلا يستطيع الشراء.**
القرار المطلوب من مالك المنتج، وأحد خيارين:

1. لا يُفتح البيع من الموقع قبل نشر التطبيق. (المسار المصمَّم عليه الباك إند)
2. تعديل في الباك إند يُنشئ الحساب عند الشراء ويرسل كلمة مرور — خارج نطاق CN-001 حاليًا.

### 2.2 مفاتيح ومتغيرات لازمة للتشغيل

القناة مقفلة افتراضيًا وتردّ `503 WEB_CHECKOUT_DISABLED`. وفي الإنتاج يرفض الباك إند الإقلاع
إذا فُعّل البيع بدون هذه (`app/core/config.py`):

| المتغير | القيمة | ملاحظة |
|---|---|---|
| `WEB_PAYMENTS_PROVIDER` | `moyasar` | `fake` مرفوض في الإنتاج |
| `MOYASAR_SECRET_KEY` | `sk_...` | من لوحة ميسّر |
| `MOYASAR_WEBHOOK_SECRET` | سر يُضبط في لوحة ميسّر | |
| `WEB_CATALOG_ENABLED` / `WEB_CHECKOUT_ENABLED` | `true` | العرض والبيع |
| `WEB_ALLOWED_ORIGINS` | دومين الموقع بالضبط، https | غيره ⇒ `403 ORIGIN_NOT_ALLOWED` |
| `CORS_ALLOWED_ORIGINS` | يشمل دومين الموقع | غيره ⇒ المتصفح يمنع الطلب |
| `WEB_CHECKOUT_RETURN_URL` | `https://<الدومين>/checkout.html` | لا بد أن يكون على العنوان نفسه الذي بدأ منه الشراء |
| `WEB_SUPPORT_CONTACT` | بريد/رقم الدعم | يظهر في شاشات الفشل والاسترداد |
| `WEB_MAIL_PROVIDER=smtp` + `WEB_MAIL_FROM` + `WEB_MAIL_SMTP_HOST` | | إيصال الشراء |

**webhook ميسّر** يحتاج أن يصل إلى الباك إند من الإنترنت. على جهاز محلي يلزم نفق (ngrok أو ما يشبهه).

### 2.3 قدرات غير موجودة، والواجهة بُنيت حولها

| المطلوب في جدول التعديلات | الحالة في الباك إند | ما فعلته الواجهة |
|---|---|---|
| LP-03: تحقق بالبريد برمز (OTP) | غير موجود ولن يُضاف | البريد مرتين + الموافقة على الشروط |
| LP-07: سجل المشتريات ومدد الوصول على الموقع | غير موجود | صفحة إرشاد: المشتريات في التطبيق |
| LP-07: طلب استرداد من الموقع | غير موجود — الاسترداد من لوحة ميسّر عبر الدعم | إرشاد بالتواصل مع الدعم برقم المرجع |

### 2.4 بيانات لا يوفّرها أي مسار عام

المسار العام الوحيد هو عروض الشراء. غير متاح للصفحة بدون تسجيل دخول:

- **أنواع الاختبارات** (`test_types`): لذلك بطاقتا «القدرات» و«التحصيلي» مكتوبتان في `index.html`.
  إضافة اختبار ثالث من الداشبورد **لن تظهر تلقائيًا**.
- **أعداد الدروس والأسئلة**: لذلك حُذفت كل الأرقام من الصفحة.

لجعلهما ديناميكيين يلزم مسار عام جديد، مثلًا `GET /public/catalog-stats`.

## 3. المطلوب بعد انتهاء التطبيق ورفعه

بالترتيب:

1. **نشر التطبيق** على App Store وGoogle Play، والتأكد أن التسجيل يعمل من داخله.
2. **روابط المتجرين** في `assets/js/config.js` → `links.appStore` و`links.googlePlay`.
   الأزرار تظهر تلقائيًا في الصفحة الرئيسية وصفحة الشراء وصفحة مشترياتي، وتختفي عبارة «يُنشر قريبًا».
3. **حساب ميسّر:** تفعيل طرق الدفع (mada · Visa · Apple Pay)، وتفعيل الدومين لـ Apple Pay على الويب،
   ثم تأكيد أيها مفعَّل فعلًا قبل عرض أي شعار أو اسم على الصفحة.
4. **ضبط متغيرات البيئة** في §2.2 على سيرفر الباك إند، وتسجيل عنوان الـ webhook في لوحة ميسّر.
5. **اختبار في وضع Sandbox** ببطاقة اختبار: شراء كامل حتى «تم الدفع»، والتأكد أن الدورة ظهرت
   في التطبيق على الحساب نفسه، وأن الإيصال وصل بالبريد.
6. **بيانات الواجهة:** `api.baseUrl` الحقيقي، وروابط الشروط والخصوصية والاسترداد، وبريد الدعم،
   وإضافة عنوان الـ API إلى `connect-src` في CSP داخل `checkout.html`.
7. **الدومين** في `canonical` و`og:url` و`og:image` وJSON-LD و`sitemap.xml`.
8. **قرار المحتوى الثابت:** هل STEP وIELTS واختبارات التخصصات الصحية ضمن الخطة؟ إن لم تكن،
   تُحذف من سطر الاختبارات في أعلى الصفحة ومن وسوم SEO.
9. **`mode: 'production'`** في `config.js` — يحذف أي رابط غير مضبوط بدل إظهاره معطّلًا.
10. حذف ملفات `*.bak` من الخادم.

## 4. كيف تظهر دورة جديدة على الموقع

الإضافة وحدها لا تكفي. الباك إند يرفض بيع دورة بلا محتوى، والسلسلة كاملة:

1. أنشئ الدورة وحدّد سعرها وربطها بنوع الاختبار.
2. أضف وحدة، ثم درسًا داخلها.
3. أضف محتوى للدرس ← أرسله للمراجعة ← اعتمده ← انشره.
   (نشر الدرس بدون محتوى معتمد يردّ `PUBLISH_REQUIREMENTS_NOT_MET: approved_content`)
4. انشر الدرس، ثم الوحدة، ثم الدورة.
   (نشر الدورة بلا محتوى ظاهر يردّ `PUBLISH_REQUIREMENTS_NOT_MET: content`)
5. أنشئ **عرض بيع على الموقع**: `POST /api/v1/admin/web-offers` بـ `tax_mode` و`vat_rate_bps`
   و`terms_ar` (ومدة الوصول للباقات فقط)، ثم `POST .../publish` مع ترويسة `If-Match: <revision>`.
6. تظهر البطاقة في الصفحة عند أول تحميل بعدها — الرد `Cache-Control: no-store` فلا تخزين.

أي تعديل في السعر من الداشبورد ينعكس على الموقع في التحميل التالي.
الدورات وصولها دائم، والباقات لها مدة وصول إلزامية.

## 5. التشغيل المحلي

في مجلد الباك إند:

```bash
export WEB_PAYMENTS_PROVIDER=fake WEB_CATALOG_ENABLED=true WEB_CHECKOUT_ENABLED=true \
  WEB_ALLOWED_ORIGINS='["http://localhost:4173","http://127.0.0.1:5500"]' \
  WEB_CHECKOUT_RETURN_URL='http://localhost:4173/checkout.html' \
  WEB_SUPPORT_CONTACT='support@prep.sa' WEB_MAIL_PROVIDER=fake
docker compose up -d --build --wait
docker compose exec -T api alembic upgrade head
docker compose exec -T -e BOOTSTRAP_ADMIN_EMAIL=admin@example.com \
  -e BOOTSTRAP_ADMIN_PASSWORD=AdminPass123 api python -m scripts.seed
```

الواجهة: `npx http-server . -p 4173 -c-1` ثم `http://localhost:4173`.
عنوان الصفحة يجب أن يكون ضمن `WEB_ALLOWED_ORIGINS` حرفيًا.

## 6. بنية الملفات

| الملف | دوره |
|---|---|
| `index.html` | صفحة الهبوط |
| `checkout.html` + `assets/js/checkout.js` | مسار الشراء ومتابعة حالة الطلب |
| `account.html` + `assets/js/account.js` | مشترياتي (إرشاد) |
| `assets/js/config.js` | **الإعداد الوحيد للنشر**: عنوان الـ API والروابط |
| `assets/js/api.js` | نداءات الباك إند وحفظ محاولة الشراء في `sessionStorage` |
| `assets/js/shared.js` | التنسيق ورسائل الأخطاء والروابط وشارة المعاينة |
| `assets/js/landing.js` | بناء بطاقات الدورات والباقات من العروض |
| `assets/js/main.js` | تفاعلات الصفحة |
